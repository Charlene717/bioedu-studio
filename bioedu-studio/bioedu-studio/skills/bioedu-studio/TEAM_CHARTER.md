# BioEdu Studio 團隊憲章（所有 agent 共同遵守）

這份憲章是全隊共用的規則。某個系列（Q/B/C…）的 `_製作慣例.md` 若與這份衝突，**以系列自己的慣例為準**，並把差異回報給總監。

## 一、使用者的鐵則（違反就是出事）

1. **動既有檔案前**：先讀懂使用者改了什麼，再備份到 `_backup/YYYYMMDD-HHMM_<原因>/`，並分清楚哪些是產物、哪些是原始碼（詳見 `backup-before-edit` skill）。
2. **不要覆蓋使用者的手改。** pptx 重建前先用 `tools/diff_pptx.py` 比對；不是這次要改的差異，一律當成使用者手改，先回填進原始碼再重建。
3. **版面問題用版面解，不要刪內容。** 太擠時，調整欄寬、行高、字級，或拆成兩頁。
4. **敘述保守。** 「一定」「只有」「唯一」這類絕對句要改成有條件的說法，並補上反例和失效情境。對學生的語氣要親切，少用命令句。
5. **pptx／docx／png／pdf 是產物，不是原始碼。** 要改就改 spec、講稿 md 或 make_*.py，再重建。

## 二、學生教材與對內檔案的邊界

| 上 GitHub（`github/`，給學生） | 永不上傳（專案根目錄，`_` 開頭） |
|---|---|
| slides PDF、R/Python 腳本、練習題、參考庫、自測題庫、README、LICENSE | `_課程簡報單.md`、`_製作慣例.md`、`_課程版本紀錄.md`、選題理由、給助教的建議、逐字稿、所有 `.docx`、`promo/` 草稿 |

如果發現學生教材裡混進了對內內容，要把它**搬到對內檔案**，不要直接刪掉。

## 三、雙語規範

- 中文用**台灣繁體**和台灣學界慣用譯名。第一次出現的術語寫成「中文（English）」，例如：批次效應（batch effect）。
- 中英兩版的**章節編號、圖號、題號必須一一對應**。
- 英文版要寫成道地的學術英文，不能讀起來像逐字翻譯。
- 圖用 `T(zh, en)` 加上 `FIGLANG=en`；規格檔用 `t(zh, en)`，兩種語言共用同一份原始碼。

## 四、科學正確性

- 每一個事實陳述都要找得到來源（DOI、官方文件，或寫明套件版本）。查不到就標 `[待查證]`，交給 domain-scientist 處理。
- 套件版本要寫死（例如 Seurat 5.x、Scanpy 1.10.x）。指令和 API 要在實際能跑的環境驗證過。
- 示範資料要用**公開、可再散布**的資料集，並註明授權（例如 10x PBMC 3k，或 GEO accession）。

## 五、無障礙與授權

- **顏色不可以是唯一的編碼**：線條要搭配不同線型，類別要搭配形狀，callout 要有圖示或標題文字。
- 色票只能從 `_deck-engine/themes.js` 取用，對比度至少 4.5:1。
- 圖片只能用自己畫的、CC-BY／CC0 授權的，或是取得使用許可的；來源和授權都要記進 `references.md`。
- 影片要附 SRT 字幕（中英各一份）。

## 六、交接規則

- 每位 agent 的產出都寫進專案資料夾裡**約定好的位置**（見總監 skill 的目錄表），回報時只交代：產出清單、待決問題，以及下一棒需要知道的事。
- 只改自己負責的資料夾。要動別人的產出，要在回報裡提出建議，由總監協調。
- 沒把握的地方，寫進產出檔的 `## 待決問題` 段落，不要自己猜。
